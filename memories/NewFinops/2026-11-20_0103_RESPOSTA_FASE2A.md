## 2. Código que força o read-only (`backend/Infrastructure/FinopsDb.cs`)

```csharp
public static NpgsqlDataSource BuildReadOnlyDataSource(string connectionString)
{
    var builder = new NpgsqlDataSourceBuilder(connectionString);
    var csb = builder.ConnectionStringBuilder;

    // Parâmetro de sessão enviado no startup da conexão: toda transação nasce READ ONLY.
    const string readOnlyOption = "-c default_transaction_read_only=on";
    csb.Options = string.IsNullOrWhiteSpace(csb.Options) ? readOnlyOption : $"{csb.Options} {readOnlyOption}";

    csb.ApplicationName ??= "CloudVista";
    return builder.Build();
}
```

Com isso, qualquer `INSERT/UPDATE/DELETE/DDL` numa conexão desse data source é recusado pelo próprio Postgres ("cannot execute ... in a read-only transaction"). O `Options` da connection string do Coolify, se já existir, é preservado (concatenado). O `ApplicationName = CloudVista` permite identificar as conexões no `pg_stat_activity`.

## 3. `/api/health/db` (`backend/Controllers/HealthController.cs`)

```csharp
[HttpGet("db")]   // autenticado pelo filtro global (sem [AllowAnonymous])
public async Task<IActionResult> GetDb(CancellationToken cancellationToken)
{
    if (!_db.IsConfigured)
        return Ok(new { status = "nao_configurado", latencyMs = (long?)null, database = (string?)null, serverVersion = (string?)null, readOnly = (bool?)null });

    var sw = Stopwatch.StartNew();
    try
    {
        await using var conn = await _db.OpenConnectionAsync(cancellationToken);

        string database, serverVersion;
        await using (var cmd = conn.CreateCommand())
        {
            cmd.CommandText = "SELECT current_database(), current_setting('server_version')";
            await using var reader = await cmd.ExecuteReaderAsync(cancellationToken);
            await reader.ReadAsync(cancellationToken);
            database = reader.GetString(0);
            serverVersion = reader.GetString(1);
        }

        // Prova de read-only por leitura: valor efetivo do parâmetro da sessão (esperado "on").
        bool readOnly;
        await using (var cmd = conn.CreateCommand())
        {
            cmd.CommandText = "SHOW default_transaction_read_only";
            readOnly = (await cmd.ExecuteScalarAsync(cancellationToken)) as string == "on";
        }
        sw.Stop();

        return Ok(new { status = "ok", latencyMs = sw.ElapsedMilliseconds, database, serverVersion, readOnly });
    }
    catch (Exception ex)
    {
        sw.Stop();
        _logger.LogError(ex, "Falha no health check do finopsdatabase.");   // detalhe só no log do servidor
        return StatusCode(503, new { status = "erro", latencyMs = sw.ElapsedMilliseconds, database = (string?)null, serverVersion = (string?)null, readOnly = (bool?)null });
    }
}
```

**Respostas possíveis:** `ok` (200), `nao_configurado` (200) e `erro` (503, sem detalhe). Host, usuário e mensagem de exceção nunca vão para o cliente.

## 5. Pontos de atenção para o teste no Coolify

1. **Se o `/api/health/db` responder `erro`:** o detalhe está no log do container (`Falha no health check do finopsdatabase`). As causas mais prováveis são rede/firewall entre o Coolify e o Postgres, ou SSL (pode precisar de `SSL Mode=Require` ou `Prefer` na connection string).
2. **PgBouncer:** se a conexão passar por um PgBouncer em modo *transaction*, ele pode recusar o parâmetro de startup `options` ("unsupported startup parameter: options"). Nesse caso, o plano B é aplicar o read-only com `UsePhysicalConnectionInitializer` (`SET SESSION CHARACTERISTICS AS TRANSACTION READ ONLY` ao abrir cada conexão física). Se acontecer, me avise que eu troco.
3. **`readOnly: false`** nunca deveria aparecer. Se aparecer, algo na connection string do Coolify está sobrescrevendo o `Options`, e é preciso investigar antes de qualquer consulta a dados.
