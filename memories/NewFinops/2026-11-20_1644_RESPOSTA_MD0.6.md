## 1. "Coletar agora": `POST /api/contas/{id}/coletar` `{ tipoJob, costDays? }`

Tudo numa transação com contexto RLS, nesta ordem:
1. **Perfil:** lê `coleta.manual.perfis_permitidos` **a cada chamada** (array JSON de strings). JSON ausente, inválido ou com outro formato → **nega todo mundo** e loga um aviso; perfil fora da lista → **403** "Seu perfil não pode disparar coletas."
2. **Conta e credencial:** inexistente ou invisível → 404; conta ou cliente inativo → 400; credencial ≠ `ATIVA` → **400** "Teste a credencial antes de coletar."
3. **Intervalo mínimo:** último job `MANUAL` de coleta da conta comparado com `coleta.manual.intervalo_minimo_min`. Dentro do intervalo → **429** "Aguarde N min para coletar esta conta novamente." N é arredondado para cima: faltando 30 s, mostra 1 min.
4. **Insert** com `ON CONFLICT DO NOTHING` (MANUAL, prioridade 10, `solicitado_por`, `escopo = {"cost_days": N}` quando informado). Sem linha → **409** "Já existe uma coleta em andamento para esta conta." Sucesso → **202** `{ jobId }`.

Validações: `tipoJob` ∈ COMPLETA/CUSTO/INVENTARIO; `costDays` entre 30 e 92.

## 3. Agenda (Configurações → Agenda)

- **API:**
  - `GET /api/admin/agenda` (Analista lê) devolve `{ itens, atalhos }`;
  - **`POST /api/admin/agenda/previa`** `{ cron, fuso }` (Analista) → `{ valida, motivo, proximas[3] }`;
  - `POST`, `PUT /{id}` e `PATCH /{id}/ativo`, só **Administrador**.
- **Validação com Quartz.NET** (pacote `Quartz` 3.13.1 adicionado ao backend):
  - 6 ou 7 campos e `CronExpression.IsValidExpression`, com mensagem que lembra o `?` em dia do mês ou dia da semana;
  - fuso vazio vira `America/Sao_Paulo`; fuso inexistente → "Fuso horário inexistente.";
  - **próximas 3 execuções** calculadas com `CronExpression { TimeZone = fuso }` e devolvidas no offset do fuso.
- **Alvo:** todas as contas, um cliente **ou** uma conta (os dois juntos → 400). Alvo inexistente (FK) → 400.
- **Gravação:** `parametros = {"cost_days": N}` quando informado; `atualizado_por` = e-mail do admin; `atualizado_em = now()`.
- **Tela:** tabela com nome, tipo, alvo, cron, fuso, situação e quem atualizou, mais editar e ativar/desativar. O formulário tem os **atalhos** ("Diário 03:00", "A cada 6 horas", "Dias úteis 07:00") e **prévia ao vivo** (a cada digitação, com 350 ms de atraso) das próximas 3 execuções por extenso. O botão Salvar fica desabilitado com cron inválido. Inclui o lembrete de que o worker relê a cada `agenda.sincronizar_seg`.

## 6. Desvios e decisões

1. **`GET /api/coletas/permissao`** (endpoint a mais): o MD pede que o botão "só apareça para perfis permitidos", e a lista mora num parâmetro do banco. Assim o front não precisa adivinhar pelo perfil.
2. **`POST /api/admin/agenda/previa`** (endpoint a mais): é a prévia "antes de salvar" calculada pelo Quartz no backend. Também valida no POST/PUT.
3. **Contas inativas não aparecem como coletáveis** no modal da página Coletas (só ativas com credencial `ATIVA`). O backend aplica a mesma regra.
4. **A agenda só aparece em Configurações**, que é uma página só de admin. O analista tem leitura pela API (`GET /api/admin/agenda`), mas ainda não há tela de agenda para ele. Se quiser, coloco uma visão de leitura dentro de Coletas.
5. `atualizado_em` de `job_agenda` e de `parametro` é gravado explicitamente com `now()` (não sei se há trigger nessas tabelas; se houver, não faz mal).
