### 2.1 Consumo da fila (sem broker)
```sql
UPDATE job_execucao
SET status = 'EXECUTANDO', iniciado_em = now(), heartbeat_em = now(),
    executor = %(executor)s, tentativas = tentativas + 1
WHERE id = (SELECT id FROM job_execucao
            WHERE status = 'PENDENTE'
            ORDER BY prioridade, criado_em
            FOR UPDATE SKIP LOCKED
            LIMIT 1)
RETURNING id, tipo_job, cliente_id, cloud_conta_id, escopo;
```
- `executor` = hostname do container. Um job por vez (concorrência 1 nesta fase).
- **Heartbeat** (thread) atualiza `heartbeat_em` a cada `coletor.heartbeat_seg` enquanto o job roda (o Zelador do worker usa isso).
- Encerramento: `CONCLUIDO`/`COLETADO`/`ERRO` com `finalizado_em` (e `coletado_em` quando houver coleta), `erro` (≤1000, **sanitizado**), `resumo` (jsonb), `coletor_versao` (versão do serviço + `COLLECTOR_VERSION` do Maurício, ex.: `cv-0.1.0/oci-1.48.0`).
- SIGTERM: termina o job atual (ou devolve para `PENDENTE` se não começou a coletar) e sai.

### 2.2 Decifrar a credencial (contrato do MD 0.3)
```sql
SELECT cr.id, cr.tipo, cr.versao_formato, cr.conteudo_cifrado,
       cd.versao_kek, cd.dek_cifrada, cc.cliente_id, cc.provedor, cc.identificador
FROM credencial cr
JOIN chave_dados cd ON cd.id = cr.chave_dados_id
JOIN cloud_conta cc ON cc.id = cr.cloud_conta_id
WHERE cr.cloud_conta_id = %(conta)s;
```
- Blob v1: `0x01 | nonce(12) | ct | tag(16)`; `AESGCM(chave).decrypt(nonce, ct||tag, aad)`.
- DEK: KEK `CV_MASTER_KEY_V{versao_kek}`, AAD `cv:dek:v1:{cliente_id}:{versao_kek}`. Credencial: AAD `cv:cred:v1:{cloud_conta_id}:{tipo}`.
- **Prova de interoperabilidade obrigatória:** `pytest` que lê `tests/vetores/cofre_v1.json` (o mesmo do C#) e decifra os 3 casos. (Eu já conferi os vetores com `cryptography` aqui: os 3 batem e recusam AAD errado.)
- Texto claro em `bytearray` quando possível e descartado logo após montar o config; **nunca** logar, nunca gravar em disco, nunca incluir em `resumo`/`erro`.
- Credencial ausente ou `DESATIVADA` → job `ERRO` ("Conta sem credencial ativa").

### 2.3 `TESTE_CREDENCIAL` (todos os provedores) — chamadas mínimas, só leitura
| Tipo | Teste |
|---|---|
| `OCI_API_KEY` | `IdentityClient(config).get_tenancy(tenancy_ocid)` + `list_region_subscriptions` |
| `AWS_ACCESS_KEY` | `sts.get_caller_identity()` |
| `AWS_ASSUME_ROLE` | `sts.assume_role(...)` e `get_caller_identity()` com a sessão assumida |
| `AZURE_SERVICE_PRINCIPAL` | `ClientSecretCredential(...).get_token("https://management.azure.com/.default")` |
| `GCP_SERVICE_ACCOUNT` | `service_account.Credentials.from_service_account_info(...).refresh(Request())` (escopo `cloud-platform.read-only`) |

- Timeout `coletor.timeout_teste_seg`. Resultado em `credencial` (`status` = `ATIVA` ou `FALHA_TESTE`, `testada_em`, `teste_resultado` ≤300 **sanitizado**, ex.: "OK: tenancy ultragaz, 4 regiões" / "Falha: autenticação recusada (401)"), auditoria `TESTADA_OK`/`TESTADA_FALHA` (`origem = 'COLETOR'`, `usuario_id` null) e job `CONCLUIDO` (sucesso) ou `ERRO` (falha) com `resumo`.

### 2.4 `COLETA_CUSTO` / `COLETA_INVENTARIO` / `COLETA_COMPLETA`
- **OCI:** roda o coletor do Maurício com o `AuthContext` adaptado. `COLETA_INVENTARIO` → `with_cost=False`; `COLETA_CUSTO` e `COLETA_COMPLETA` → `with_cost=True` (`cost_days` de `escopo.cost_days` ou 90). `client_name` = nome do cliente; `executed_by` = "CloudVista".
  - Saída: o `dict` do `run()` → JSON UTF-8 → gzip → `INSERT INTO coleta_bruta (job_execucao_id, formato, tamanho_bytes, sha256, conteudo)` → job `COLETADO` com `resumo` = `{ recursos, regioes, meses_custo, erros_nao_fatais, duracao_seg }` (contagens; nada sensível). Coleta só com erros não fatais **é sucesso**; exceção fatal → `ERRO`.
  - `out_path`: se o `run()` exigir arquivo, use um temporário e apague (o JSON não tem segredo, mas é dado de cliente — não deixe no container).
- **AWS / AZURE / GCP:** job `ERRO` com "Coleta deste provedor ainda não disponível (próximas fases)". (O teste de credencial deles funciona desde já.)
