## 0. Contexto

Cada cliente (ex.: Ultragaz) tem **N contas de cloud**: tenancies OCI, contas/organização AWS, tenant/subscriptions Azure, organização/projetos GCP. A conta é a unidade que o coletor (MD 0.5) vai varrer. **Credenciais NÃO fazem parte deste MD** — o cofre cifrado é o MD 0.3 (as tabelas já existem, mas **não toque** em `credencial`, `chave_dados` e `credencial_auditoria` agora).

Regras de sempre: você **não** conecta nem testa no banco; SQL parametrizado; só tokens/`ui-*` no front; nada de segredo em log.

## 1. Tabela (DDL executada pelo HLGDR — não recriar)

`cloud_conta`:

| Coluna | Tipo / regra |
|---|---|
| `id` | bigint identity PK |
| `cliente_id` | bigint FK `cliente` |
| `provedor` | varchar(10) CHECK `OCI`,`AWS`,`AZURE`,`GCP` |
| `nome` | varchar(150) — nome amigável (ex.: "OCI Ultragaz principal") |
| `identificador` | varchar(200) — OCID da tenancy / account id / tenant ou subscription id / org ou project id |
| `escopo` | varchar(20) CHECK `TENANCY`,`CONTA`,`ORGANIZACAO`,`TENANT`,`SUBSCRICAO`,`PROJETO` |
| `regiao_padrao` | varchar(50) null (ex.: `sa-saopaulo-1`, `us-east-1`) |
| `ativo` | bool |
| `criado_em`, `atualizado_em` | timestamptz (trigger) |
| | **UNIQUE (`provedor`, `identificador`)** |

RLS (`svc_cv_api`): **SELECT** se `app_cliente_visivel(cliente_id)` (admin = todas; analista/cliente = dos clientes vinculados). **INSERT/UPDATE só ADMINISTRADOR.** Sem DELETE (desativação via `ativo`). Worker e coletor leem todas.

Função nova no banco: `app_cliente_visivel(p_cliente_id bigint) → boolean` (admin ou vínculo em `usuario_cliente`). Use o helper `ExecutarComContextoAsync` de sempre.

## 2. Validação por provedor (backend é a autoridade; front espelha)

| Provedor | Escopos válidos | Formato do `identificador` |
|---|---|---|
| OCI | `TENANCY` | `^ocid1\.tenancy\.oc1\.\.[a-z0-9]+$` |
| AWS | `CONTA`, `ORGANIZACAO` | `CONTA`: 12 dígitos · `ORGANIZACAO`: 12 dígitos (account id da **payer/management**) |
| AZURE | `TENANT`, `SUBSCRICAO` | GUID (`^[0-9a-fA-F]{8}-([0-9a-fA-F]{4}-){3}[0-9a-fA-F]{12}$`), gravar em minúsculas |
| GCP | `ORGANIZACAO`, `PROJETO` | `ORGANIZACAO`: só dígitos · `PROJETO`: `^[a-z][a-z0-9-]{4,28}[a-z0-9]$` |

- `identificador` com `trim`; duplicado (23505) → **409** "Esta conta já está cadastrada (provedor + identificador)." — a mensagem **não** revela de qual cliente é.
- Conta só pode ser criada para **cliente ativo**. `regiao_padrao` livre (≤50), opcional.
- `provedor` e `identificador` **não mudam** após criados (editar só `nome`, `escopo` quando compatível, `regiao_padrao`).

## 3. API

- `GET /api/contas?clienteId=&provedor=&incluirInativas=false` — política **Autorizado** (RLS filtra o que cada perfil vê). Retorna `id, clienteId, clienteNome, provedor, nome, identificador, escopo, regiaoPadrao, ativo, criadoEm` + `credencialStatus: null` (placeholder; preenchido no MD 0.3).
- `POST /api/admin/contas` `{ clienteId, provedor, nome, identificador, escopo, regiaoPadrao? }` — **Administrador**.
- `PUT /api/admin/contas/{id}` `{ nome, escopo, regiaoPadrao? }` — **Administrador**.
- `PATCH /api/admin/contas/{id}/ativo` `{ ativo }` — **Administrador**.
- Erros: 400 (validação, com mensagem por campo), 404, 409.

## 4. Frontend

- **Configurações** ganha a aba **Contas de cloud** (admin): tabela (cliente, provedor com ícone/rótulo, nome, identificador em fonte mono **truncado com tooltip**, escopo, região, situação), filtros por cliente e provedor, "Nova conta", editar, ativar/desativar (com confirmação).
- Formulário: escolher **Cliente** → **Provedor** → o campo **Escopo** só oferece os válidos daquele provedor → **Identificador** com placeholder/ajuda do formato do provedor (ex.: "ocid1.tenancy.oc1..aaaa…") e validação ao digitar.
- Na aba **Clientes**, mostrar a contagem de contas ativas por cliente (coluna "Contas").
- Menu: novo item **"Contas de cloud"** na seção **Negócio** (antes de Configurações), visível para **todos os perfis**, rota `/contas-de-cloud`: lista **somente leitura** (mesmos filtros) — é o que o Analista e o Cliente vão usar para ver as contas deles. Para o Administrador, um botão "Gerenciar" leva à aba de Configurações.
- Rótulos dos provedores: "OCI", "AWS", "Azure", "GCP". Sem logos de terceiros nesta fase (só texto/ícone genérico `lucide`).
