## 1. Criptografia (`backend/Cofre/`)

| Arquivo | Conteúdo |
|---|---|
| `CofreCripto.cs` | AES-256-GCM (`AesGcm`), formato v1 `0x01 \| nonce(12) \| ct \| tag(16)`. O nonce é novo por cifragem (`RandomNumberGenerator`). `CifrarComNonce` é `internal` e serve só aos vetores (`InternalsVisibleTo` do projeto de testes). AAD `cv:dek:v1:{cliente_id}:{versao_kek}` e `cv:cred:v1:{cloud_conta_id}:{tipo}`. Decifrar recusa versão ≠ 1, tamanho inválido, chave ≠ 32 bytes e falha de tag/AAD, sempre com mensagem genérica e zerando o buffer de saída |
| `ChavesMestras.cs` | Lê `CV_MASTER_KEY_V{n}` (várias versões ao mesmo tempo) e `CV_MASTER_KEY_ATUAL` do `IConfiguration` (variáveis de ambiente). Cada chave precisa ser base64 de exatamente 32 bytes. Uma chave inválida é ignorada, e o log cita **só o nome da variável**. Atual ausente/inválida ou apontando para versão não carregada → cofre desativado, sem derrubar o app |
| `CredencialRegras.cs` | Os 5 tipos, campos, formatos, dica e limite de 16 KB (seção 3) |
| `CofreServico.cs` | SQL e transações (seção 2) |
| `CredencialController.cs` | Endpoints + `CofreErrosFilter` |

**Higiene de memória:**
- DEK e JSON em texto claro são zerados (`CryptographicOperations.ZeroMemory`) no `finally`.
- O buffer interno do `MemoryStream` da serialização também é zerado.
- A DEK não fica em cache.
- **Limitação:** os valores chegam ao controller como `string` do .NET (imutáveis, não dá para zerar), porque é assim que o JSON é desserializado. Eles ficam na memória até o GC. Zerar isso exigiria ler o corpo como bytes e fazer o parse manual; não fiz nesta fase.

## 2. Banco (sempre via `ExecutarComContextoAsync`)

- **`conteudo_cifrado` nunca é lido:**
  - nenhum `SELECT`/`RETURNING` toca na coluna;
  - o upsert usa **parâmetros no `SET`**, e não `EXCLUDED.conteudo_cifrado`. Ler `EXCLUDED.*` no `ON CONFLICT DO UPDATE` exige SELECT na coluna, que o `svc_cv_api` não tem;
  - o `RETURNING` devolve só o `id`.
- **DEK:**
  - `pg_advisory_xact_lock(0x4356444B, cliente_id)` serializa a criação da primeira DEK do cliente. Sem isso, duas gravações simultâneas poderiam bater no índice "1 DEK ativa por cliente";
  - depois busca a DEK ativa e a decifra com a KEK da versão em que foi cifrada; se não existir, gera 32 bytes, cifra com a KEK atual e insere, **na mesma transação**.
- **Auditoria:** `CADASTRADA`/`SUBSTITUIDA` com o detalhe "aceite de credencial somente leitura confirmado", e também `DESATIVADA`/`REATIVADA` e `TESTE_SOLICITADO`, sempre com `origem = 'API'`.

```sql
SELECT cc.cliente_id, cc.provedor, cc.identificador FROM cloud_conta cc WHERE cc.id = @conta_id
SELECT pg_advisory_xact_lock(@namespace, @cliente_id)
SELECT id, versao_kek, dek_cifrada FROM chave_dados WHERE cliente_id = @cliente_id AND ativa
INSERT INTO chave_dados (cliente_id, versao_kek, dek_cifrada, ativa) VALUES (@cliente_id, @versao_kek, @dek_cifrada, true) RETURNING id
SELECT id, status FROM credencial WHERE cloud_conta_id = @conta_id
INSERT INTO credencial (cloud_conta_id, chave_dados_id, tipo, versao_formato, conteudo_cifrado, dica, status, cadastrada_por)
VALUES (@conta_id, @chave_dados_id, @tipo, @versao_formato, @conteudo, @dica, @status, @usuario_id)
ON CONFLICT (cloud_conta_id) DO UPDATE SET
    chave_dados_id = @chave_dados_id, tipo = @tipo, versao_formato = @versao_formato, conteudo_cifrado = @conteudo,
    dica = @dica, status = @status, testada_em = NULL, teste_resultado = NULL,
    cadastrada_por = @usuario_id, cadastrada_em = now()
RETURNING id
UPDATE credencial SET status = @status, testada_em = NULL, teste_resultado = NULL WHERE cloud_conta_id = @conta_id
INSERT INTO credencial_auditoria (cloud_conta_id, credencial_id, acao, detalhe, usuario_id, origem) VALUES (@conta_id, @credencial_id, @acao, @detalhe, @usuario_id, 'API')
SELECT cr.id, cr.tipo, cr.dica, cr.status, cr.testada_em, cr.teste_resultado, u.nome, cr.cadastrada_em
FROM credencial cr LEFT JOIN usuario u ON u.id = cr.cadastrada_por WHERE cr.cloud_conta_id = @conta_id
SELECT a.acao, a.detalhe, u.nome, a.origem, a.ocorrido_em FROM credencial_auditoria a
LEFT JOIN usuario u ON u.id = a.usuario_id WHERE a.cloud_conta_id = @conta_id ORDER BY a.ocorrido_em DESC LIMIT 200
```
`GET /api/contas` agora faz `LEFT JOIN credencial cr ON cr.cloud_conta_id = cc.id` e devolve `cr.status` em `credencialStatus`.

## 3. Tipos e validação (`CredencialRegras`)

| Tipo | Validações | Dica |
|---|---|---|
| `OCI_API_KEY` | `user_ocid` `ocid1.user.oc1..`; `tenancy_ocid` no formato **e igual ao identificador da conta**; `fingerprint` 16 pares hex (normalizado para minúsculas); `region` como `sa-saopaulo-1`; PEM começa com `-----BEGIN`; `passphrase` opcional (sem trim) | `…` + últimos 5 do fingerprint |
| `AWS_ACCESS_KEY` | `access_key_id` `^(AKIA\|ASIA)[A-Z0-9]{16}$`; `secret_access_key` 40 caracteres `[A-Za-z0-9/+=]` | `…` + últimos 4 do key id |
| `AWS_ASSUME_ROLE` | Os da access key + `role_arn` `arn:aws:iam::<12>:role/<nome>` + `external_id` opcional (2 a 1224 caracteres) | `…XXXX · <nome do role>` |
| `AZURE_SERVICE_PRINCIPAL` | `tenant_id` e `client_id` GUID (normalizados para minúsculas), `client_secret` ≤ 1024 | `…` + últimos 4 do client id |
| `GCP_SERVICE_ACCOUNT` | JSON válido, objeto, `type = "service_account"`, `client_email` com `@` e `private_key` presente | `client_email` |

Regras comuns:
- tipo compatível com o provedor da conta;
- campos fora da lista do tipo são recusados;
- obrigatórios checados; `trim`, exceto na passphrase;
- JSON serializado só com os campos permitidos, em ordem fixa;
- **limite de 16 KB**;
- dica com no máximo 40 caracteres.

**Nenhuma mensagem de erro contém o valor recebido**, só o nome do campo e o formato esperado. Nem a mensagem do parser de JSON é repassada.

## 4. API

| Endpoint | Política | Comportamento |
|---|---|---|
| `GET /api/contas/{id}/credencial` | Autorizado | `{ existe, tipo, dica, status, testadaEm, testeResultado, cadastradaPorNome, cadastradaEm }` |
| `PUT /api/contas/{id}/credencial` | **AdministradorOuCliente** (política nova); o RLS restringe ao próprio cliente | `aceiteSomenteLeitura` precisa ser `true` (400). Cofre desativado → 503 "Cofre de credenciais não configurado." Resposta: os metadados |
| `PATCH /api/contas/{id}/credencial/ativo` | Administrador | `DESATIVADA` ↔ `PENDENTE_TESTE` + auditoria. Sem credencial → 404 |
| `POST /api/contas/{id}/credencial/testar` | Autorizado (quem enxerga a conta) | Auditoria `TESTE_SOLICITADO` → **202** com a mensagem do MD. Sem credencial ou credencial desativada → 409 |
| `GET /api/contas/{id}/credencial/auditoria` | Autorizado | Até 200 itens; usuário nulo vira "Sistema" |
| `GET /api/health` | Anônimo | Ganhou `cofre: "ok" \| "nao_configurado"` |

- Conta invisível para o usuário (RLS) → 404.
- **`CofreErrosFilter`:** nunca loga a mensagem de exceção, só o **tipo** e o **SQLSTATE**. `42501` (permissão/RLS) → 403 "Você não tem permissão para esta operação nesta conta."; demais erros → 500 genérico.
- Nada loga o corpo das requisições: não há middleware de request logging.

## 8. Desvios e observações

1. **Push protection do GitHub:** o primeiro push foi **bloqueado** porque o teste tinha um access key id **falso** no formato `AKIA` + 16 caracteres. **Não usei o link de liberação.** Corrigi o commit ainda não enviado: o teste monta o valor em tempo de execução, e os vetores usam `EXEMPLO-FALSO-NAO-E-CHAVE`. O repositório não tem nenhum literal no formato de chave AWS. É bom saber, para o coletor: o push protection está ativo no repo.
2. **Upsert sem `EXCLUDED.*`:** foi para respeitar a falta de SELECT em `conteudo_cifrado` (seção 2). O comportamento é o mesmo do `ON CONFLICT DO UPDATE` pedido.
3. **Advisory lock na criação da DEK:** evita violar o índice "1 ativa por cliente" em gravações simultâneas. Não estava no MD.
4. **`POST /testar` com credencial inexistente ou desativada → 409** (o MD não definia).
5. **Strings imutáveis** do .NET com os segredos ficam na memória até o GC (seção 1).
6. `teste_resultado`/`testada_em` são limpos na substituição e na reativação; ao desativar, também são limpos.
