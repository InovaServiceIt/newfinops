# Ajuste MD 0.5 — log de falha de conexão do coletor sem diagnóstico

**De:** Claude (chat) · **Para:** VSClaude · **Data:** 20/11/2026 13:55 (Brasília) · **Prioridade:** alta (bloqueia o aceite)

No primeiro deploy do `cloudvista-collector`, o log só mostrou:
```
CRITICAL cloudvista.coletor: Não foi possível conectar ao banco (CV_DB_URL). Tipo do erro: OperationalError.
```
(repetindo a cada ~2 s). Sem a causa, não dá para diagnosticar (senha? host? SSL? URL malformada?).

**Ajuste:**
1. Em falha de conexão, logar também a **mensagem do psycopg sanitizada**: a mensagem do libpq **não** contém a senha, mas pode ecoar a URL em erros de parse — então: remova qualquer trecho no formato `scheme://user:senha@` (regex substituindo a senha por `***`), remova o valor completo de `CV_DB_URL` se aparecer literalmente, corte em 300 caracteres. Exemplos que DEVEM aparecer: `password authentication failed for user "svc_cv_collector"`, `connection to server at "x.x.x.x", port 5432 failed: timeout`, `SSL ... not supported`, `invalid connection option`/`invalid URI`.
2. **Backoff** nas tentativas de conexão: 2 s → 5 s → 15 s → 30 s → 60 s (teto), em vez de ~2 s fixo.
3. Teste `pytest`: dada uma exceção cuja mensagem contém `postgresql://svc_cv_collector:SEGREDO_TESTE_X@host/db`, o log resultante não contém `SEGREDO_TESTE_X` e contém `***`.
4. Mesma revisão no worker C# se ele tiver o mesmo padrão (a `NpgsqlException`/`PostgresException` de conexão é segura para logar a mensagem; só a de parse da connection string não é — já tratada no `LogSeguro`).

Entrega: commit no `main` + `RESPOSTA_AJUSTE_MD0.5.md`.
