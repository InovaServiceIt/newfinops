## 1. "Coletar agora"

`POST /api/contas/{id}/coletar` `{ tipoJob: "COLETA_COMPLETA" | "COLETA_CUSTO" | "COLETA_INVENTARIO", costDays?: 30..92 }`
- **Quem pode:** perfis listados em `parametro['coleta.manual.perfis_permitidos']` (JSON; hoje `["ADMINISTRADOR","ANALISTA_FINOPS"]`) — lido do banco a cada chamada (sem deploy para liberar o Cliente no futuro). Fora da lista → 403 "Seu perfil não pode disparar coletas." (O RLS também barra CLIENTE em coleta — defesa em profundidade.)
- **Pré-condições:** conta ativa de cliente ativo; credencial `ATIVA` (senão 400 "Teste a credencial antes de coletar.").
- **Intervalo mínimo:** se existir job `origem = 'MANUAL'` de coleta para a mesma conta criado há menos de `coleta.manual.intervalo_minimo_min` minutos → **429** "Aguarde N min para coletar esta conta novamente." (calcular N).
- **Duplicidade:** job da mesma conta+tipo em `PENDENTE/EXECUTANDO` → **409** "Já existe uma coleta em andamento para esta conta." (use o `ON CONFLICT DO NOTHING` + verificação, como no 0.4).
- Insere com `origem = 'MANUAL'`, `prioridade = 10`, `solicitado_por`, `escopo = { "cost_days": N }` quando informado. Resposta **202** `{ jobId }`.

## 3. Agenda (Configurações → aba "Agenda")

- `GET /api/admin/agenda` (ADMIN e ANALISTA leem), `POST/PUT /api/admin/agenda`, `PATCH /api/admin/agenda/{id}/ativo` (só ADMIN).
- Campos: nome, tipo (`COLETA_COMPLETA/CUSTO/INVENTARIO`), alvo (todas as contas / um cliente / uma conta), cron, fuso (padrão `America/Sao_Paulo`), `parametros.cost_days` opcional.
- **Cron no formato Quartz** (6–7 campos). Validar no backend com **Quartz.NET** (`CronExpression.IsValidExpression`) e mostrar **as próximas 3 execuções** calculadas no fuso escolhido (prévia antes de salvar). Atalhos prontos: "Diário 03:00" (`0 0 3 * * ?`), "A cada 6 horas" (`0 0 0/6 * * ?`), "Dias úteis 07:00" (`0 0 7 ? * MON-FRI`).
- Lembrete na tela: o worker relê a agenda a cada `agenda.sincronizar_seg` (60 s) — não precisa reiniciar nada.
- `atualizado_por` = e-mail do admin.
