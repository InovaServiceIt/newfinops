## 0. Por que isso é crítico

Aqui ficam as credenciais read-only das clouds dos clientes (Ultragaz). Um erro aqui é incidente de segurança. Regras inegociáveis:
- **O segredo nunca volta**: nenhum endpoint devolve o conteúdo; a tela é de "mão única".
- **Nada de segredo em log**, exceção, telemetria ou resposta de erro (nem parcial). Não logar o corpo das requisições de credencial.
- **A API não consegue ler o segredo do banco**: o usuário `svc_cv_api` **não tem SELECT** na coluna `credencial.conteudo_cifrado` (só INSERT/UPDATE). Quem decifra é o coletor Python (MD 0.5). **Nunca** escreva `SELECT *`/`RETURNING *` em `credencial` (falha por permissão — e é proposital).
- Você continua **sem** acesso ao banco: código + build + testes.

## 2. Criptografia — especificação (contrato com o coletor Python; não improvisar)

**Algoritmo:** AES-256-GCM (`System.Security.Cryptography.AesGcm`), nonce **12 bytes** aleatório (`RandomNumberGenerator`) **por cifragem**, tag **16 bytes**.

**Formato binário (v1)** — igual para `dek_cifrada` e `conteudo_cifrado`:
```
[0]      = 0x01                 (versão do formato)
[1..12]  = nonce (12 bytes)
[13..n-17] = texto cifrado
[n-16..n-1] = tag (16 bytes)
```
(É o layout que o `cryptography.hazmat.primitives.ciphers.aead.AESGCM` do Python consome: `decrypt(nonce, ct || tag, aad)`.)

**KEK (chave mestra):** variáveis `CV_MASTER_KEY_V{n}` (base64 de **32 bytes**) e `CV_MASTER_KEY_ATUAL` (= `n`). Carregar no startup; validar tamanho; **ausente/inválida → cofre desativado** (endpoints de gravação 503 `"Cofre de credenciais não configurado."`, health `cofre: "nao_configurado"`), sem derrubar o app e **sem logar o valor**. Suportar várias versões carregadas ao mesmo tempo (rotação futura).

**DEK (por cliente):** 32 bytes aleatórios, criada **na primeira credencial do cliente** (na mesma transação), cifrada com a KEK atual:
- AAD da DEK: `cv:dek:v1:{cliente_id}:{versao_kek}` (UTF-8).

**Conteúdo da credencial:** JSON UTF-8 (campos do §3) cifrado com a DEK ativa do cliente:
- AAD: `cv:cred:v1:{cloud_conta_id}:{tipo}` (UTF-8) — amarra o segredo à conta e ao tipo (trocar linhas de lugar no banco quebra a decifragem).

**Higiene de memória:** zerar arrays de DEK/texto claro após uso (`CryptographicOperations.ZeroMemory`); não manter DEK em cache.

**Vetores de teste (obrigatório):** gerar `tests/vetores/cofre_v1.json` com 3 casos determinísticos (chave fixa, nonce fixo, AAD, texto claro → hex do blob v1) — o coletor Python (MD 0.5) vai usar o MESMO arquivo para provar interoperabilidade. A função de cifragem real usa nonce aleatório; os vetores usam uma sobrecarga interna com nonce injetado (só para teste).

## 3. Tipos de credencial e campos

| Tipo | Provedor | Campos (JSON) | `dica` (nunca o segredo) |
|---|---|---|---|
| `OCI_API_KEY` | OCI | `user_ocid`, `tenancy_ocid`, `fingerprint`, `region`, `private_key_pem`, `passphrase?` | últimos 5 do `fingerprint` |
| `AWS_ACCESS_KEY` | AWS | `access_key_id`, `secret_access_key` | últimos 4 do `access_key_id` |
| `AWS_ASSUME_ROLE` | AWS | `access_key_id`, `secret_access_key`, `role_arn`, `external_id?` | últimos 4 do `access_key_id` + nome do role |
| `AZURE_SERVICE_PRINCIPAL` | AZURE | `tenant_id`, `client_id`, `client_secret` | últimos 4 do `client_id` |
| `GCP_SERVICE_ACCOUNT` | GCP | `service_account_json` (conteúdo do arquivo JSON da SA) | `client_email` extraído do JSON |

Validações: tipo compatível com o provedor da conta; `tenancy_ocid` igual ao `identificador` da conta OCI; formato de OCIDs/ARN/GUID; PEM começa com `-----BEGIN`; JSON da SA válido com `type = "service_account"` e `client_email`; tamanho máximo do payload 16 KB. Mensagens de erro **nunca** ecoam o valor recebido.

## 4. API

Todas sob contexto RLS (`ExecutarComContextoAsync`).
- `GET /api/contas/{id}/credencial` — **Autorizado**: `{ existe, tipo, dica, status, testadaEm, testeResultado, cadastradaPorNome, cadastradaEm }` (nunca conteúdo).
- `PUT /api/contas/{id}/credencial` — **ADMINISTRADOR ou CLIENTE** (o RLS garante o "do próprio cliente"): body `{ tipo, campos: {...}, aceiteSomenteLeitura: true }`.
  - `aceiteSomenteLeitura` **obrigatório = true** (400 se faltar).
  - Na mesma transação: obtém/cria DEK ativa do cliente → cifra → `INSERT ... ON CONFLICT (cloud_conta_id) DO UPDATE` (status `PENDENTE_TESTE`, limpa `testada_em`/`teste_resultado`, atualiza `cadastrada_por/em`) **sem `RETURNING conteudo_cifrado`** → auditoria `CADASTRADA` ou `SUBSTITUIDA` (detalhe: "aceite de credencial somente leitura confirmado").
  - Resposta: os mesmos metadados do GET.
- `PATCH /api/contas/{id}/credencial/ativo` `{ ativo }` — **ADMINISTRADOR**: `DESATIVADA` ↔ `PENDENTE_TESTE` + auditoria.
- `POST /api/contas/{id}/credencial/testar` — **qualquer perfil que enxergue a conta**: registra auditoria `TESTE_SOLICITADO` e responde **202** `{ mensagem: "Teste registrado. Ele será executado quando o coletor estiver ativo." }` (a execução real vem no MD 0.5, pela fila do MD 0.4).
- `GET /api/contas/{id}/credencial/auditoria` — **Autorizado**: lista (ação, detalhe, nome do usuário ou "Sistema", origem, quando).
- `GET /api/contas` (MD 0.2) passa a preencher `credencialStatus` (null = sem credencial).
- `/api/health` ganha `cofre: "ok" | "nao_configurado"` (sem detalhes).
