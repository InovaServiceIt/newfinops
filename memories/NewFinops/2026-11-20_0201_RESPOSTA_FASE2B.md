**Desempenho:** o resumo é lido **2 vezes** por requisição de Visão Geral (seção 4, consultas F e G). A primeira traz os totais **diários** do intervalo inteiro; os meses, as projeções, os 12 meses e o custo diário saem dela, em C#. A segunda traz dia × serviço × SKU × região só da segunda da semana passada até ontem (no máximo 13 dias); os dois blocos de Top 5 saem dela. As duas filtram por `cloudproviderid` **e** pelo `id_provedor` do `recurso_nuvem` (join), como o Grafana.

**Contrato da API:**
- `GET /api/visao-geral/opcoes?provedor=3` → `{ provedores[{id,tipo,nome,cliente,rotulo}], provedorSelecionado, anos[], servicos[], skus[], regioes[], fator }`.
- `GET /api/visao-geral?provedor=3&ano=2026&meses=1&meses=2&servicos=…&skus=…&regioes=…&comFator=false` → `{ provedor, nomeProvedor, ano, comFator, fator, referencias{hoje, mesAtual, ultimoMesFechado, semanaAnteriorInicio, semanaAnteriorFim, ontem}, orcamentoMensal, indicadores{orcamentoAnual, acumuladoAno, ultimoMes, mesAtual, projecaoMes, projecaoAnual: {valor, percentualOrcamento, referencia}}, custoMensal[{ano,mes,rotulo,valor,projecao,faixa}], ultimosDozeMeses[{…,parcial}], semanaAnterior{inicio,fim,total,topServicos,topSkus,topRegioes}, diaAnterior{…}, custoDiario[{dia,valor}] }`.
- Listas vazias significam "todos". `faixa` ∈ `ok | atencao | acima | sem_orcamento`.

## 2. Regras implementadas (e onde corrigem o Grafana)

| Bloco | Regra |
|---|---|
| Orçamento anual | `SUM(valor_previsto)` de `orcamento` do(s) cliente(s) do provedor com `periodo = ano`. Sem orçamento → card "Sem orçamento cadastrado para <ano>" *(no Grafana era fixo)* |
| Acumulado do ano | Soma do **ano selecionado**, respeitando o filtro de **Mês** |
| Último mês / Mês atual | Mês fechado anterior / mês corrente até hoje (independem do ano selecionado, como no Grafana) |
| Projeção do mês | Média dos **3 meses fechados** anteriores (só os que têm dados, igual ao `AVG` com `GROUP BY` do Grafana) |
| Projeção anual | **Corrigida**: fechados do ano + projeção do mês + projeção × meses restantes após o atual. *(O Grafana fazia a média incluindo o mês parcial)* |
| % nos cards | Acumulado e projeção anual vs orçamento anual; último mês, mês atual e projeção do mês vs orçamento mensal (anual ÷ 12) |
| Custo mensal | Meses do ano selecionado (filtro Mês) + barra "Projeção mês atual" (só quando o ano é o atual). Faixa vs anual ÷ 12: ≤ 90% `ok`, ≤ 100% `atencao`, > 100% `acima`, sem orçamento `sem_orcamento` |
| Últimos 12 meses | **Dados reais** *(o painel do Grafana era `randomWalk`)*: 12 meses fechados + mês atual (marcado como parcial) |
| Semana anterior | **Segunda a domingo da semana passada** (datas do C#; atravessa mês e ano) *(o Grafana só olhava o mês atual e incluía a semana corrente)* |
| Dia anterior | **Exatamente ontem** em São Paulo *(o Grafana usava `dia >= ontem`, somando hoje)* |
| Top 5 | Exatamente 5 *(o Grafana usava `LIMIT 6`)*, respeitando **todos** os filtros *(no Grafana os Top 5 de serviço/região do dia ignoravam filtros)* |
| Custo diário | Dias do mês corrente |
| Com fator | Multiplica **todos os custos** por `fator_cliente.fator` (cadastro mais recente do provedor). **O orçamento não é multiplicado.** Sem fator → chave desabilitada com tooltip |
| Região | Nula ou vazia → "(sem região)". Serviço e SKU vazios → "(sem serviço)" / "(sem SKU)". O mesmo rótulo vale no filtro e no resultado |

**Mapeamento de nomes** (confirmado nos JSONs): no Grafana, a variável `$servico` filtra `rn.nome` (= **SKU**) e `$recurso` filtra `rn.tipo_recurso` (= **Serviço**). No CloudVista, "Serviço" = `tipo_recurso` e "SKU" = `nome`, como no MD.

## 4. Consultas SQL (texto completo)

Todas são parametrizadas (`@nome`), sem `SELECT *`, rodando em sessão `default_transaction_read_only=on`. Os únicos literais no SQL são os rótulos fixos `'(sem serviço)'`, `'(sem SKU)'` e `'(sem região)'`. Os arrays (`@servicos`, `@skus`, `@regioes`) são `text[]`; vazio = todos.

### A. Provedores (opções e nome do provedor)
```sql
SELECT p.id_provedor, p.tipo, p.nome, cl.nome AS cliente
FROM svc_finops.provedor_nuvem p
LEFT JOIN svc_finops.contrato ct ON ct.id_contrato = p.id_contrato
LEFT JOIN svc_finops.cliente  cl ON cl.id_cliente  = ct.id_cliente
ORDER BY p.id_provedor
```
*(nunca seleciona `config_de_acesso`)*

### B. Anos com dados
```sql
SELECT DISTINCT rm.ano::int AS ano
FROM svc_finops.resumo_soma_dia_mes_ano_recurso rm
WHERE rm.cloudproviderid = @provedor
ORDER BY ano DESC
```

### C. Serviços / D. SKUs / E. Regiões (listas dos filtros)
```sql
SELECT DISTINCT COALESCE(NULLIF(rn.tipo_recurso, ''), '(sem serviço)') AS valor
FROM svc_finops.recurso_nuvem rn
WHERE rn.id_provedor = @provedor
ORDER BY valor
```
```sql
SELECT DISTINCT COALESCE(NULLIF(rn.nome, ''), '(sem SKU)') AS valor
FROM svc_finops.recurso_nuvem rn
WHERE rn.id_provedor = @provedor
ORDER BY valor
```
```sql
SELECT DISTINCT COALESCE(NULLIF(rn.regiao, ''), '(sem região)') AS valor
FROM svc_finops.recurso_nuvem rn
WHERE rn.id_provedor = @provedor
ORDER BY valor
```

### F. Totais diários do intervalo (custo mensal, acumulado, último mês, mês atual, projeções, 12 meses, custo diário)
```sql
SELECT rm.ano::int AS ano, rm.mes::int AS mes, rm.dia::int AS dia, SUM(rm.total_custo) AS total
FROM svc_finops.resumo_soma_dia_mes_ano_recurso rm
JOIN svc_finops.recurso_nuvem rn ON rn.id_recurso = rm.id_recurso_resumo
WHERE rm.cloudproviderid = @provedor
  AND rn.id_provedor = @provedor
  AND (rm.ano, rm.mes) >= (@ano_ini, @mes_ini)
  AND (rm.ano, rm.mes) <= (@ano_fim, @mes_fim)
  AND (cardinality(@servicos) = 0 OR COALESCE(NULLIF(rn.tipo_recurso, ''), '(sem serviço)') = ANY(@servicos))
  AND (cardinality(@skus)     = 0 OR COALESCE(NULLIF(rn.nome, ''), '(sem SKU)')     = ANY(@skus))
  AND (cardinality(@regioes)  = 0 OR COALESCE(NULLIF(rn.regiao, ''), '(sem região)')  = ANY(@regioes))
GROUP BY rm.ano, rm.mes, rm.dia
```
O intervalo é calculado no C#: do menor entre (jan do ano selecionado) e (12 meses antes do mês atual) até o maior entre (dez do ano selecionado) e (mês atual). Exemplo para hoje (nov/2026) com ano 2026: 2025-11 a 2026-12. Com ano 2024: 2024-01 a 2026-11.

### G. Totais por dia × serviço × SKU × região (semana anterior e dia anterior)
```sql
SELECT make_date(rm.ano::int, rm.mes::int, rm.dia::int) AS data,
       COALESCE(NULLIF(rn.tipo_recurso, ''), '(sem serviço)') AS servico,
       COALESCE(NULLIF(rn.nome, ''), '(sem SKU)')     AS sku,
       COALESCE(NULLIF(rn.regiao, ''), '(sem região)')  AS regiao,
       SUM(rm.total_custo) AS total
FROM svc_finops.resumo_soma_dia_mes_ano_recurso rm
JOIN svc_finops.recurso_nuvem rn ON rn.id_recurso = rm.id_recurso_resumo
WHERE rm.cloudproviderid = @provedor
  AND rn.id_provedor = @provedor
  AND (rm.ano, rm.mes) >= (@ano_ini, @mes_ini)
  AND (rm.ano, rm.mes) <= (@ano_fim, @mes_fim)
  AND make_date(rm.ano::int, rm.mes::int, rm.dia::int) BETWEEN @data_ini AND @data_fim
  AND (cardinality(@servicos) = 0 OR COALESCE(NULLIF(rn.tipo_recurso, ''), '(sem serviço)') = ANY(@servicos))
  AND (cardinality(@skus)     = 0 OR COALESCE(NULLIF(rn.nome, ''), '(sem SKU)')     = ANY(@skus))
  AND (cardinality(@regioes)  = 0 OR COALESCE(NULLIF(rn.regiao, ''), '(sem região)')  = ANY(@regioes))
GROUP BY 1, 2, 3, 4
```
`@data_ini` = segunda da semana passada e `@data_fim` = ontem (`date`). `@ano_ini/@mes_ini` e `@ano_fim/@mes_fim` são os meses dessas duas datas: o filtro por `(ano, mes)` reduz as linhas antes do `make_date`.

### H. Orçamento por ano
```sql
SELECT o.periodo, SUM(o.valor_previsto) AS valor_previsto
FROM svc_finops.orcamento o
WHERE o.id_cliente IN (
    SELECT ct.id_cliente
    FROM svc_finops.provedor_nuvem p
    JOIN svc_finops.contrato ct ON ct.id_contrato = p.id_contrato
    WHERE p.id_provedor = @provedor)
  AND o.periodo = ANY(@periodos)
GROUP BY o.periodo
```
`@periodos` = `{ano selecionado, ano atual, ano do último mês fechado}` como texto.

### I. Fator
```sql
SELECT fc.fator
FROM svc_finops.fator_cliente fc
WHERE fc.id_provedor = @provedor
ORDER BY fc.id DESC
LIMIT 1
```

**Por requisição:** opções = A, B, C, D, E e I; Visão Geral = A, F, G, H e I. Cada uma roda numa única transação.

## 7. Pontos de atenção / dúvidas

1. **Tabela × view:** o Grafana lê `vw_resumo_soma_dia_mes_ano_recurso` (view) na maioria dos painéis e a **tabela** `resumo_soma_dia_mes_ano_recurso` só no gráfico mensal. Usei a **tabela**, como o MD pede. Se a view existir justamente para contornar o DROP/CREATE, ou tiver alguma regra a mais, é uma troca de nome em `VisaoGeralSql.cs`.
2. **Orçamento:** se o cliente tiver mais de uma linha de `orcamento` para o mesmo `periodo`, **somo** os `valor_previsto`. Se o certo for pegar só uma (a mais recente, por exemplo), me avise.
3. **Fator:** uso o cadastro mais recente (`ORDER BY id DESC LIMIT 1`) e **multiplico** o custo. Confirmar se o fator multiplica (e não divide).
4. **Consulta B (anos)** faz um `DISTINCT` no resumo inteiro do provedor. Ela fica em cache por 5 min, mas pode ser a mais lenta: vale olhar o tempo no log.
5. **Cor no skin light:** o `--accent` do light é o vermelho Service IT. Por isso as barras do custo diário, a área "sem orçamento" e as barras dos Top 5 ficam vermelhas, o que pode lembrar "acima do orçamento". Sugestão: usar `--accent-2` (azul) nas séries neutras do light. Não troquei sem a decisão do HLGDR.
6. O `npm audit` agora aponta 11 vulnerabilidades (antes 10), por causa do `recharts` e das dependências dele. Entra no pacote de atualização de dependências.
